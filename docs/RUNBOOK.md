# 故障处置

只记录当前骨架里能够执行的检查。支付、账本和 LiteLLM 转发还没有业务路径，那些场景不能假装已经演练过。

## 业务 API 无法启动

看进程退出前的校验错误。`APP_ENV=production` 且 mock、演示模型或开发口令仍开启时，进程会故意退出。改环境变量，不要改校验去迁就错误配置。

## /readyz 返回 503

读 `data.checks`。`postgres` 或 `redis` 为 `unavailable` 时，先确认对应进程和 `DATABASE_URL` / `REDIS_URL`。开发编排把数据库端口绑在 127.0.0.1。容器内应使用主机名 `postgres` 和 `redis`，不要把容器里的 URL 写成 127.0.0.1。

响应里的状态词只有 `ok` 和 `unavailable`，不包含连接串。

## 前端显示业务后端不可达

BFF 默认访问 `API_INTERNAL_URL`，缺省是 `http://127.0.0.1:8000`。在 Compose 网络里应设为 `http://api:8000`。先单独请求 `/healthz`，确认是后端没起来，还是只是浏览器到 BFF 的路径错了。

## 初始化令牌打了两次

脚本发现 `.data/admin_init_token.sha256` 已存在会拒绝再次生成。不要为了看明文去改脚本。丢失明文就删除摘要后重新生成，并确认旧令牌没有被使用。
