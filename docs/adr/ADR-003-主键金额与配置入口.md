# ADR-003：主键、金额与配置入口

- 状态：已接受
- 日期：2026-10-28
- 背景与问题：

需求要求全库统一主键，金额禁止浮点，配置禁止散落读取环境变量。这些选择会贯穿后续迁移，第一阶段就要定下来。

- 备选方案（含不做的理由）：

1. bigint 自增主键。索引紧凑，但会暴露数据规模，也不利于以后多实例生成。
2. 数据库端 UUIDv7。PostgreSQL 16 没有内置 `uuidv7()`。为了这个函数引入扩展不值得。
3. 应用生成 UUID v4，列类型用 PostgreSQL `uuid`。随机主键有索引分裂，但第一阶段数据量不是瓶颈，生成方式不依赖数据库版本。

金额用 `NUMERIC`，API 层用十进制字符串。配置只经过 `pydantic-settings`。时钟通过 `Clock` 注入。业务 API 由浏览器访问 Next.js 的 `/api/*`，再由 Route Handler 转发到 FastAPI，并原样转发 Cookie。

- 决策：

采用 UUID v4。金额在数据库中使用 `NUMERIC`，序列化为字符串。环境变量只在 `app/core/config.py` 读取。公开模型 API `/v1/*` 以后由 Nginx 直达 FastAPI，避免流式响应再绕一层 Node。

产品代号 ForgeAPI，指标前缀 `forgeapi_`。对外名称是「算力中转站」。

- 影响与后果（正面/负面）：

正面：主键、金额和配置入口后面不用再改一次迁移策略。负面：UUID 索引比 bigint 大；BFF 多一跳，只用于带 Cookie 的业务 API。

- 验证方式：

身份表迁移使用 `postgresql.UUID`。配置测试覆盖生产环境保护。BFF 单测覆盖路径拼接和路径穿越拒绝。
