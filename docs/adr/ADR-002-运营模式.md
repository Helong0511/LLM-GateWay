# ADR-002：默认海外运营模式

- 状态：已接受
- 日期：2026-10-28
- 背景与问题：

需求 §1.1 要求部署时在大陆模式与海外模式中显式选择一种，禁止混用。当前工作区没有营业执照、微信或支付宝商户号，也没有已完成的大陆合规材料。验收标准却明确要求 USDT 订单的伪造回调、确认数和幂等用例。

- 备选方案（含不做的理由）：

1. 大陆模式（CNY、微信/支付宝）。符合中文运营习惯，但没有商户号，开发期只能停在 mock，且无法覆盖 v3.0 的加密货币验收项。
2. 两种模式同时开启。需求明确禁止。
3. 海外模式（USD、Stripe + USDT 托管网关）。开发期用法币 mock 和 USDT mock，生产必须换成真实渠道。界面保持简体中文，不做框架级 i18n。

- 决策：

默认 `OPERATING_MODE=overseas`。结算币种为 USD。法币渠道预留 Stripe，加密货币渠道预留托管网关；第一阶段资金代码尚未实现，当前只把模式写进配置和 `/api/meta`。

运行中的进程只读这一个模式。大陆适配器以后可以存在于代码里，但海外模式启动时不得注册微信/支付宝，反之亦然。海外模式不得向中国大陆居民提供加密货币相关服务，这项限制在支付上线前必须落到注册协议和地区筛查，不能只写在配置注释里。

切换模式属于上线前的配置变更。已经产生账本之后不允许直接改币种。

- 影响与后果（正面/负面）：

正面：验收所需的 USDT 规则有明确归属，开发不依赖大陆支付牌照。负面：若实际要在大陆运营，需要在任何真实充值之前改回 mainland，并停用 USDT 渠道。

- 验证方式：

`/api/meta` 返回 `operating_mode`。生产配置校验见 `Settings._production_guards`。支付渠道是否真正按模式隔离，留到阶段 6 的 TC-PAY-* 证明。
