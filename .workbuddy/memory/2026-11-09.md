## 全量代码审查（LLM-GateWay / ForgeAPI）

- 产出：`docs/CODE_REVIEW_2026-11-09.md`（P0 5 / P1 7 / P2 8 / P3 3）。
- 方法：全量阅读 apps/api/app（88 模块）+ apps/web/src；新建 `.venv-review/` 跑 ruff / mypy / pytest。
- 检查结果：compileall 通过、ruff 通过、mypy 通过（88 files）、pytest 6 failed / 98 passed。
- 关键结论（P0）：
  1. Stripe/USDT「主动查单」为进程内 dict 占位（payments/gateways.py），真实充值必然失败。
  2. `WorkerSettings` 无 `cron_jobs`，`release_expired_holds` 永不执行。
  3. `gateway/service.py complete()/embeddings()` 上游异常不释放预扣。
  4. `ledger.py:82` 抛 `BALANCE_INSUFFICIENT`，`billing/service.py:117` 与 `ledger.py:268` 比对 `INSUFFICIENT_BALANCE`，disputed 兜底失效。
  5. 代理链 IP 丢失：uvicorn 无 `--proxy-headers`、nginx `/v1/` 无 XFF、BFF 不透传 XFF → 注册限流变全站、IP 白名单失效。
- 测试失败根因：`gateway/service.py` 优先 `upstream_client`，测试注入的 `upstream_transport` 被忽略。
- 附带改动：`.gitignore` 加入 `.venv-review/`。

## 修复与架构补齐（承接审查）

- P0 全部关闭：支付网关真实查单（Stripe Checkout + USDT HTTP，新增 `provider_ref`/`provider_snapshot`，迁移 0018）；worker 补 `cron_jobs`；上游异常 `_settle_unsuccessful` 结清预扣；余额错误码统一为常量 `BALANCE_INSUFFICIENT`；IP 透传三处联动 + `core/request_ip.py`。
- P1：测试替身改为 transport 优先（网关 + providers 两处）；Cookie 拼接；CSP/HSTS；请求体累计字节限流；优惠券条件更新；bootstrap 串行化；唯一冲突映射 409；TOTP 时间步水位（迁移 0019）。
- P2：限流/并发闸 Redis 化（`RedisRateLimiter`/`RedisSlots`，故障降级）；热点行写入 60s 节流；RBAC 种子补全。
- 架构断链（本轮新增）：模型上架只写自家库、LiteLLM `model_list` 为空 → 新增 `providers/litellm_registry.py`，上架/下架/换凭证/部署启停同步 Admin API（幂等键 `model_info.id = deployment.id`），`registry_synced_at`/`registry_error`（迁移 0020）+ worker 每 10 分钟对账；`deploy/litellm/config.yaml` 开 `store_model_in_db: true`。
- nginx：`/v1/` 读超时 180s→600s 并补 send timeout；`location /` 补 `X-Real-IP`（nginx 同层定义即不继承）。
- 请求体限流踩坑：FastAPI 会把 body 读取阶段任意异常兜底成 400，中间件不能靠抛异常；改为「截断输入 + 丢弃应用响应 + 自回 413」。
- 测试：`FORGE_TEST_PG_DSN` 可配，且非表属主时 skip（避免环境红）。最终 ruff/mypy 通过，pytest 104 passed / 1 skipped。
